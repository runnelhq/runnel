# Testplan und bekannte Einschränkungen

Stand: nach Phase 0.5 (S38c). Dieses Dokument beschreibt, wie der aktuelle Stand geprüft wird – automatisch
und manuell unter Windows – und welche Einschränkungen bekannt sind.

## 1. Automatische Prüfungen

| Prüfung | Wann | Befehl |
|---|---|---|
| Lint (golangci-lint) für Linux- und Windows-Code | jeder PR, `main` | `make lint` |
| Unit-, Golden- und CLI-Tests mit Race-Detector | jeder PR (Linux), ohne Race-Detector (Windows) | `make test` |
| Schwachstellen (`govulncheck`) | jeder PR, wöchentlich | `make vulncheck` |
| Editor: Typprüfung und Playwright-Tests (E2E) | jeder PR | `make e2e` |
| Fuzzing von Workflow-, Pipeline- und Trigger-Dateien, Variablen, Ausdrücken, Zahlen-/Datumsformaten, CSV-Eingabe und HTTP-Anfragen an Trigger | wöchentlich (5 min je Ziel), lokal bei Bedarf | `make fuzz FUZZTIME=2m` |
| Build, Packen, SBOM | jeder PR | `make package` |
| Benchmarks (Lastproben, z. B. HTTP-Trigger) | lokal bei Änderungen an Pfaden unter Last, Werte im PR | `make bench` |

Testabdeckung (Anweisungen, Stand S38c): `engine/pipeline` 94 %, `triggers` 93 %, `model` 90 %, `engine/workflow` 90 %,
`server` 90 %, `runs` 89 %, `vars` 87 %, `cli` 81 %, `actions/core` 70 %.

Vom Fuzzing gefundene Eingaben werden unter `internal/model/testdata/fuzz/` gespeichert und laufen danach bei jedem
`go test` als Regressionstest mit.

## 2. Manueller Test unter Windows

Vorbereitung: Release `v0.1.0-alpha.2` (oder neuer) herunterladen, ZIP entpacken, PowerShell im entpackten Ordner öffnen.
Für die Beispiele zusätzlich das Repository als ZIP herunterladen (*Code → Download ZIP*) und den Ordner `examples`
daneben legen.

**Wozu:** Der manuelle Test deckt ab, was die CI nicht prüfen kann – Windows-Dienst, Netzlaufwerke und UNC-Pfade, Excel,
ein zweiter Rechner, verschiedene Browser, SmartScreen. Alles andere gehört in Go- oder Playwright-Tests. Neue Tests
kommen nur mit dieser Begründung hinzu ([AGENTS.md](../AGENTS.md#arbeitsweise)), in den passenden Bereich; die Nummern
bleiben, weil PRs und Ergebnisse auf sie verweisen.

**Je Release:** die **Kurzauswahl** W1, W2, W4, W9, W12, W19, W26, W36, W46, W48, W49 und W51 sowie alle Tests, die seit
dem letzten Release neu sind („ab dem ersten Release nach …“). Die übrigen bei Bedarf, z. B. nach Änderungen im Bereich.
